## 画面とスクロール

検討では元の盤面幅・高さ・駒・持ち駒・評価グラフ・操作部を変更しない。広告上端を「元の内容末尾」と「ビューポート下端」の遅い方より下へ置く。広告取得によって画面高を減らす固定フッターや、盤面上の重ね表示は使わない。

Androidは計画段階の外側ScrollView案から変更し、Canvasの既存スクロールを保ったFrameLayoutに実際のNativeAdViewを子として配置する。画面高・描画倍率・駒の入力座標を変えず、スクロール量に合わせて広告ビューを移動する。広告内からの縦スワイプは親が引き継ぎ、SDKへACTION_CANCELが届く。画像化した広告や自前のクリック転送は使わない。

iOSは既存のScrollView内の末尾へUIViewRepresentableによるSDKビューを追加する。UIKitの広告素材・クリック・AdChoicesはSDKが扱う。盤面の比率・幅・内側の8pt間隔を維持する。

広告と解析・棋譜操作の間には余白を設ける。実際のSDK素材とAdChoicesを表示するため、広告枠は参考画像の薄いバナーより背が高い360dp/ptのカードで確保した。見出し・説明・媒体名・CTAは配信内容を使い、画像・動画はSDKのMediaViewで表示する。

## テスト通信と本番対応の区別

- 通常起動はGoogleの公式テスト広告を実際に要求する。広告取得には通信が必要。失敗した場合は広告枠に取得失敗を表示し、対局・検討を継続できる。
- 非パーソナライズのリクエストを使用し、動画はミュートで開始する。AndroidのAD_ID権限はマージで除去する。iOSはATTを要求せずIDFAへアクセスするコードを追加しない。
- Googleの公開サンプルアプリIDには運営者の同意メッセージを設定できないため、このテスト専用版には本番用UMPフローを入れていない。本番広告へ移行する前には、運営者のAdMob登録・app-ads.txt・同意メッセージ・必要なATTとストア申告を整え、同意に基づく要求制御を実装する。広告ユニットIDを単純に差し替えて本番利用してはいけない。
- 広告SDKの追加でAPKサイズと通信の有無が変わる。SDK内部にはWebViewが含まれるが、将棋盤のUIやAIは引き続きネイティブ実装である。従来の「DEXにWebViewが一切存在しない」「APK25MB未満」という検証条件を、ネイティブ盤面の維持と広告SDKを含むサイズの確認へ更新した。
- 設定画面にテスト広告であることと広告通信の説明を追加する。収益化は行わない。

## 検証

Androidの既存NativeSmokeTestとiOSの既存UIフローは、再現性のため広告の取得を模したフィクスチャーを使用する。フィクスチャーには「配信広告ではありません」と表示し、成功・失敗を再現する。通常のAPK・IPA起動はフィクスチャーを使用しない。

追加した検証は次を区別して記録する。

1. **固定フィクスチャーのレイアウト・回帰テスト**：初期表示で広告が画面外、成功・失敗でも寸法維持、広告までスクロール、盤面へ戻る、合法手の着手、既存の棋譜・AI・時計・SEの回帰。
2. **実SDKの公式テスト広告要求**：別起動でフィクスチャーを無効にし、公式SDKの取得結果（loaded / failed）を保存する。ネットワーク上の配信失敗は回復可能状態として記録し、「実広告取得成功」とは扱わない。自動テストでは配信広告のクリックを行わない。

Androidの結果は `test_ads.txt` と `44_ads_*`〜`49_ads_*` のスクリーンショット。iOSはxcresultの `11-ads-*`〜`15-ads-*` と `official-test-ad-result` 添付。各成果物の取得結果を確認して、フィクスチャーの合格とSDKからの広告取得を区別する。

実機での音・動画・広告先アプリへの遷移は別途確認する。iOSのActions成果物は未署名IPAとSimulatorアプリであり、実機配布にはAppleの署名が必要。

参考：[GoogleのAndroidテスト広告](https://developers.google.com/admob/android/test-ads)、[iOSネイティブ広告](https://developers.google.com/admob/ios/native/advanced)、[本番移行の実装計画](ads-implementation-plan.md)。
