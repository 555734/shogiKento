# クリップボードからのKIF取り込み（Android v1.10.0 / 16）

前面でウィンドウにフォーカスがあるとき、起動・復帰および前面でのクリップボード変更時に、直接コピーされたテキストを確認します。平手KIFらしいヘッダーと初手が見つかった場合だけ「コピーされた棋譜を検討しますか？」を表示します。「検討する」で全手順を別スレッドで検証し、既存の検討があれば追加の置き換え確認を行ってから、最終局面を検討モードへ読み込みます。失敗時は手数と原因を表示し、既存の検討内容を維持します。

キャンセル・読み込み済みの同じ内容は、クリップボードの内容が変わるまで再提示しません。直近の内容のSHA-256だけを内部設定に保持し、任意のクリップボード本文は保存・ログ出力・送信しません。ユーザーが取り込みを承認した棋譜の盤面履歴と指し手は、従来の検討データとしてローカル保存します。履歴には初期局面を含む全手順を保持し、グラフ・「初期／前へ／次へ／最終／手順」で移動できます。読み込み棋譜は通常の自由編集の300手保持上限の対象外です。途中から編集すると、その先の古い分岐を置き換えます。

対応範囲は平手・初期配置からのKIF本譜。Shogi Questの番号付き着手・移動元・時間欄、全角／半角数字・括弧、漢数字または数字の段、空白・タブ・CRLF、「同」「成」「不成」「打」、龍／竜、成香／成桂／成銀、終局記号を処理します。合法手との照合により、移動・駒取り・持ち駒・成り・二歩・王手放置などを検証します。変化、駒落ち、途中配置、他の棋譜形式は、誤った局面として読み込まず対応外の理由を示します。安全上の上限は256K文字・4096手です。

## OSの制約と代替操作

- Android 10以降は、IMEまたはフォーカスがあるアプリだけがクリップボードを読めます。そのため、onResumeだけで読み取らず、フォーカスを得てから確認します。背景での監視やサービスは使いません。[Android公式](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data)
- Android 12以降では、内容を読むとOSがクリップボードアクセス通知を表示することがあります。棋譜かどうかは本文を読むまで判別できるため、棋譜でない場合もOSの通知までは抑止できません。アプリ自身の確認ダイアログは棋譜候補に限ります。[Android公式](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste#SystemNotification)
- OSが読み取りを拒否した場合などは、ホームの「棋譜を貼り付け」から入力欄を長押しして、OS標準の貼り付け操作を使えます。URIやContentProviderを暗黙に読み取らず、機密指定されたクリップは自動検出の対象外にします。
- iOSは今回のユーザー指示により対象外です。

## 提示棋譜と検証の境界

`tests/fixtures/shogi_quest_79.kif` はユーザー提示のShogi Quest棋譜です。79手目「８三金打」の最終局面は後手玉の詰みです。終局局面では既存の詰み表示を行い、無意味な継続探索は開始しません。78手目など、合法手がある局面へ移動した時に既存のネイティブAIで継続解析します。

JVMテストは全80局面の移動、表記揺れ、エラー、永続化、分岐、300手を超える保持を確認します。独立したpython-shogi 1.1.1のKIFパーサー／合法手判定でも79手と全80局面の盤面・持ち駒・最終詰みを照合します。

Android instrumentationには、別プロセスのテストAPKからOSクリップボードへ本文を書き込むActivityを用意しています。起動・復帰時の確認、通常文／機密クリップの無反応、キャンセル抑止、最終局面、全手順、OS経由の手順ボタン・グラフ操作、78手目での実AI継続解析、再起動復元、置き換えとエラー時の保持を検証し、`outputs/clipboard_import.txt` と画面画像に記録します。このテスト用Activityと棋譜fixtureはテストAPKだけに入り、本体APKには含みません。

Shogi Questアプリ自体でのコピー操作・物理端末での受け入れ確認とは区別します。実行結果は対象のActions runの証跡で確認してください。
